# Security Policy

## Supported versions

Security fixes are currently prepared for the latest code on the `main` branch. There is no promise of security backports to older commits or unofficial forks. Check the latest release and repository advisories for current status.

## Reporting a vulnerability

Please do not publish an exploitable vulnerability in a public issue. Use GitHub's **Report a vulnerability** action under the repository Security tab for a private advisory. Include affected commit/version, impact, reproduction steps, and a suggested mitigation if known. Do not include real credentials, personal data, or someone else's assets in the report.

If private vulnerability reporting is unavailable, contact the repository owner through the private contact details on their GitHub profile and include a safe reply channel. Avoid public disclosure until maintainers have had a reasonable opportunity to investigate and coordinate a fix.

## Scope and response

Reports affecting the engine, editor, player, asset/package loading, update/build tooling, or CI are in scope. Maintainers will acknowledge reports when able, assess impact, coordinate disclosure, and publish a fix or mitigation when appropriate. This project does not currently promise a fixed response-time SLA.

Do not run security tests against infrastructure or users you do not own or have explicit permission to assess.
